# Дополнение Config Import

## Об этом документе

Этот документ описывает импорт файлов конфигураций в CDPI UI. Импорт начинается со статического анализа исходного файла. Он заканчивается пробным запуском и сохранённым `ConfigItem` в `LocalUserStorage`.

Основная логика находится в пространстве имён `CDPIUI.AddOns.ConfigImport`. Мастер импорта находится в проекте `CDPIUI`. Мастер — клиент дополнения.

Этот документ предназначен для разработчиков и авторов пользовательской справки. Он описывает текущее поведение, ограничения и случаи, в которых результат зависит от выбранного компонента или от решения пользователя.

## Функции

Дополнение выполняет следующие задачи:

1. Импортирует файлы `.bat`, `.cmd`, `.txt` и `.json`. Оно не запускает исходный скрипт.
2. Находит подходящий установленный компонент по его `executable` и по содержимому файла.
3. Преобразует командную строку и переменные исходного файла в `ConfigItem` CDPI UI.
4. Использует специальный статический анализатор для `winws` и `winws2`.
5. Сохраняет редактируемые значения переменных BAT в `variables`, `commaVars`, `availableCommaVarsValues` и `jparams`.
6. Находит внешние ресурсы BIN, TXT и LUA, генерируемые файлы и отсутствующие зависимости.
7. Предлагает замену для отсутствующего файла. Пользователь также может выбрать пустой файл.
8. Позволяет пользователю протестировать выбранный компонент с импортированными аргументами.
9. Копирует зависимости в отдельные папки: `List/Converted`, `Bin/Converted` и `Lua/Converted`.
10. Преобразует готовую командную строку `winws1` в `winws2`, когда пользователь переносит конфигурацию на Zapret 2.
11. Передаёт пакеты `.cdpiconfig` дополнению ConfigShare. См. [ConfigShare/README.ru.md](../ConfigShare/README.ru.md).

## Принцип безопасности

Импорт статический. `ConfigImportService` и `ZapretConfigImportService` читают исходный текст, находят известные конструкции и создают модель результата. Они не запускают `cmd.exe`, PowerShell, исходный файл BAT или CMD и команды из него.

Поэтому анализ не:

- выполняет `if`, `for`, `goto`, `copy`, `del`, `reg`, `netsh` и другие команды оболочки;
- запускает вызываемые файлы BAT как процессы;
- запускает программы из исходного скрипта;
- отправляет сетевые запросы;
- изменяет исходную папку.

Кнопка **Тест** — отдельная операция. Она запускает выбранный установленный компонент через `ComponentTasksManager` с вычисленными аргументами.

ПРЕДУПРЕЖДЕНИЕ: Пробный запуск — это не песочница. Безопасность статического импорта не распространяется на пробный запуск исполняемого файла компонента.

## Модель цели

`ConfigImportTarget` содержит:

- `ComponentId`: уникальный ID компонента в БД Магазина;
- `DisplayName`: отображаемое имя;
- `Executable`: имя исполняемого файла из БД, с `.exe` или без него;
- `Version`: текущая версия компонента;
- `Directory`: папка установленного компонента.

Мастер показывает только элементы Магазина типа `component`, которые выполняют следующие условия:

1. Заданы `Id`, `Directory` и `Executable`.
2. Папка существует.
3. Исполняемый файл существует в папке. При необходимости мастер добавляет расширение `.exe`.

Поэтому компонент, который не установлен, не участвует в автоматическом определении. Мастер не может протестировать или сохранить для него конфигурацию.

## Автоматическое определение компонента

`FindMatchingTargets` работает следующим образом.

### `.cdpiconfig`

Метод читает пакет с помощью `ConfigShareService.Read`. Он выбирает цель с ID компонента из `target[0]` упакованной конфигурации. Если пакет недействителен, метод не возвращает цель. Тогда импорт сообщает подробную ошибку архива.

### JSON

Метод загружает `ConfigItem` из JSON. Он сравнивает первый элемент `target` со значениями `ComponentId` установленных компонентов.

### BAT, CMD и TXT

Метод ищет ссылку на исполняемый файл каждого установленного компонента. Имя может быть с `.exe` или без него. Форма `%~dp0<executable>` тоже допустима.

Сравнение учитывает границы имени. Например, `winws` не совпадает с частью более длинного идентификатора.

### Дополнительные сигнатуры TXT

Если в файле TXT нет явного исполняемого файла, метод использует следующие сигнатуры:

- `# BuiltinVersion: ...` или параметр `--lua-desync` означает `winws2`;
- параметр `--dpi-desync` означает `winws`.

### Приоритет цели в мастере

Мастер выбирает цель для анализа в следующем порядке:

1. первая цель, которую нашёл анализатор;
2. ID компонента из маршрута `cdpiui://Tools/ImportConfig/{componentId}`;
3. первый установленный компонент в списке;
4. пустая цель, если ни один компонент не подходит.

Для начального выбора в UI приоритет имеет компонент из маршрута, даже если анализатор нашёл другую цель. Мастер отдельно запоминает результат автоматического определения. Он использует эту запись для предупреждения о несовместимом выборе.

## Результат анализа

`ConfigImportResult` содержит:

- `SharedPackage`: извлечённый пакет `.cdpiconfig` или `null`;
- `Config`: `ConfigItem` или `null`, если анализ не удался;
- `Target`: цель анализа;
- `SourcePath`: основной импортированный файл;
- `Issues`: предупреждения и ошибки;
- `SourceFiles`: основной файл и включённые файлы конфигураций и скрипты;
- `ReferencedFiles`: существующие ресурсы, которые копирует установщик;
- `MissingReferencedFiles`: отсутствующие ресурсы;
- `MissingFileResolutions`: явные решения пользователя;
- `GeneratedFiles`: файлы, которые исходный BAT создаёт перед запуском.

Результат успешен, только если выполняются оба условия:

```text
Config != null
and
Issues contains no item with Severity == Error
```

Предупреждения не блокируют тест и сохранение. Ошибки блокируют обе операции.

## Импорт общего компонента

Общий анализатор применяется ко всем исполняемым файлам, кроме нормализованных имён `winws` и `winws2`.

Нормализация имени исполняемого файла удаляет папку, кавычки и конечное `.exe`. Сравнение не учитывает регистр.

### Импорт BAT и CMD

1. Анализатор читает файл с определением кодировки из анализатора Zapret (`BatchFileEncoding`): UTF-8, OEM 866 или ANSI 1251.
2. Он объединяет в одну логическую строку физические строки, которые заканчиваются нечётным числом `^`.
3. Он обрабатывает присваивания `set NAME=VALUE` и `set "NAME=VALUE"` с необязательным `@` перед `set`.
4. Он использует `set` после `rem ` или `::` как альтернативное значение переменной.
5. Он пропускает комментарии и пустые строки. Комментарий — это строка, которая начинается с `::` или `#`, или строка, которая начинается с `rem` или `@rem`, за которыми следует пробел, табуляция или конец строки.
6. Он разбивает каждую строку на токены. Двойная кавычка начинает или заканчивает часть в кавычках.
7. Он ищет токен, который после статической подстановки является исполняемым файлом выбранного компонента.
8. Текст после исполняемого файла становится строкой аргументов. Перенаправление, pipe или `&` вне кавычек отсекают остаток строки.
9. Для каждого запуска анализатор сохраняет копию переменных на момент запуска.
10. Должен существовать ровно один подходящий запуск. Если запуска нет или их несколько, импорт завершается ошибкой.

Если аргументы запуска — один токен, который указывает на существующий файл `.txt`, анализатор импортирует этот файл как содержимое конфигурации. Токен может иметь префикс `@` или `$`. Анализатор разрешает путь относительно файла BAT или CMD.

Найдя аргументы, анализатор транзитивно собирает используемые переменные. Например, если строка запуска использует `%A%`, а значение `A` использует `%B%`, результат содержит обе переменные.

### Общий импорт TXT

1. Анализатор читает файл тем же средством чтения логических строк.
2. Он пропускает пустые строки и комментарии.
3. Если строка содержит запуск выбранного исполняемого файла, анализатор удаляет исполняемый файл и оставляет только аргументы.
4. Он объединяет остальные строки через пробел.
5. Он берёт имя из комментария `# Config:`, `# Preset:` или `# ActivePreset:` (`=` тоже допустим). Без такого комментария он использует имя файла без расширения.

Пустой набор аргументов — это ошибка.

### Импорт JSON

Сначала анализатор пытается загрузить текущий `ConfigItem`. Если в JSON нет `startup_string`, анализатор пытается загрузить старый `OldConfigItem`:

- `custom_parameters` переходит в `startup_string`;
- `meta` становится `pUC:v1.0`;
- имя берётся из имени файла;
- `jparams` и `variables` пустые.

После загрузки анализатор всегда устанавливает `target` в ID выбранного компонента и его версию.

### Переменные общего импортёра

Все используемые переменные BAT попадают в `commaVars`. Основное значение получает следующие изменения:

```text
%~dp0  ->  $GETCURRENTDIR()/
\      ->  /
```

Если у переменной есть закомментированные альтернативы, анализатор создаёт элемент `availableCommaVarsValues`:

```json
{
  "VarName": "LISTS",
  "CurrentValueIndex": 0,
  "Values": [
    "$GETCURRENTDIR()/lists/default.txt",
    "$GETCURRENTDIR()/lists/alternative.txt"
  ]
}
```

Неизвестная `%VARIABLE%` в строке запуска или в значениях попадает в `commaVars` со значением `$EMPTY`. Исключения — встроенные переменные `CD`, `ERRORLEVEL`, `DATE` и `TIME`.

Общий анализатор не создаёт условные `jparams`. `jparams` и `variables` такой конфигурации пустые.

## Импорт Zapret

`ZapretConfigImportService` выполняет статический импорт для `winws` и `winws2`. В коде поколения называются `Winws1` и `Winws2`.

Импорт Zapret не преобразует синтаксис winws1 в winws2. Он создаёт конфигурацию того поколения, которое находит в исходном BAT, CMD или TXT. Только `ConfigImportService.Retarget` преобразует `winws1 -> winws2`, на более позднем шаге.

### Кодировка файлов Zapret

Анализатор читает файлы BAT, CMD и TXT через `CDPIUI.Core.System.BatchFileEncoding`. Он определяет кодировку в следующем порядке:

1. UTF-8 с BOM;
2. UTF-16 LE с BOM;
3. UTF-16 BE с BOM;
4. строгий UTF-8 без BOM;
5. кириллическая кодовая страница, если байты не являются допустимым UTF-8. Если байтов в диапазоне `0x80`–`0xAF` больше, чем в диапазоне `0xC0`–`0xFF`, кодовая страница — OEM 866 (кодовая страница `cmd`). Иначе — ANSI 1251.

Поэтому анализатор может импортировать русские наборы BAT без ручного преобразования.

### Анализ BAT и CMD Zapret

Анализатор выполняет следующие шаги:

1. Читает логические строки. Строка, которая заканчивается нечётным числом `^`, продолжается на следующей строке.
2. Загружает `PredefinedVariables`, если вызывающий код их передаёт.
3. Последовательно собирает обычные и закомментированные команды `set`.
4. Статически следует по известным вызовам внешних файлов BAT и CMD.
5. Находит запуски `winws` или `winws2`. Имя исполняемого файла не должно быть продолжением более длинного имени: `mywinws.exe` — это не запуск.
6. Сохраняет копию переменных для каждого запуска.
7. Требует ровно один запуск.
8. Раскрывает ссылку на конфигурацию TXT, например `@config.txt`.
9. Проверяет, что исполняемый файл и поколение параметров совпадают.
10. Оставляет только переменные, которые использует запуск.
11. Создаёт переключатели для условных значений и для `ACTIVE_*.bin`.
12. Находит существующие, отсутствующие и генерируемые ресурсы.
13. Создаёт `ConfigItem`.

Комментарий — это строка, которая начинается с `rem`, `@rem` или `::`. После `rem` должен следовать пробел, табуляция или конец строки. Закомментированное альтернативное значение должно начинаться с `rem ` или `::`. Анализатор не считает `@rem set ...` альтернативным значением.

Анализатор находит запуск по тексту `winws` или `winws2` с необязательным `.exe` перед кавычкой, пробелом или концом строки. После исполняемого файла должен следовать один из следующих элементов: параметры, которые начинаются с `--`, ссылка на файл TXT или переменная BAT. Это правило уменьшает число ложных совпадений со служебными строками.

Анализатор обрезает командную строку на первом `>`, `<`, `|` или `&` вне кавычек. Вне кавычек он также удаляет экранирование кареткой, как это делает `cmd`: `^&` становится `&`, а `^^` становится `^`.

Обратная косая черта в анализаторе не является символом экранирования. Поэтому папка в кавычках, которая заканчивается обратной косой чертой, например `"C:\dir\"`, правильно закрывает кавычку.

### Поддерживаемые переменные BAT

Статическая подстановка знает следующие формы:

- `%~<modifiers>0`: путь текущего файла BAT с модификаторами `f` (полный путь), `d` (диск), `p` (папка), `n` (имя) и `x` (расширение), которые комбинируются так же, как в `cmd`. Например, `%~dp0` — это папка файла BAT, а `%~n0` — его имя без расширения;
- `%0`: полный путь файла BAT;
- `%%`: литеральный знак процента. Подстановка не считает его началом переменной;
- `%NAME%`: известная переменная BAT или переменная окружения процесса CDPI UI;
- `!NAME!`: отложенная подстановка. Вместо неё конфигурация получает `%NAME%`;
- `$GETCURRENTDIR()/` и `$GETCURRENTDIR()\` в уже нормализованных значениях.

Максимальная глубина рекурсивной подстановки — 16. Неизвестная переменная остаётся в строке, и анализатор добавляет предупреждение.

### Внешние файлы BAT и CMD и `service.bat`

Анализатор знает такие вызовы:

```bat
call "path\script.bat" argument
call path\script.cmd argument
```

Вызов локальной метки, `call :label`, не является внешним файлом. Для существующего файла BAT или CMD анализатор выполняет следующие шаги:

1. Разрешает путь относительно вызывающего скрипта.
2. Если у пути нет расширения, добавляет `.bat`.
3. Добавляет файл в `SourceFiles`.
4. Статически собирает переменные файла.
5. Объединяет результат с переменными вызывающего файла.

Если первый аргумент вызова совпадает с конструкцией вида `if "%~1"=="argument" (...)`, анализатор читает метки `call :label` в этом блоке. Если он не находит такой диспетчеризации, он читает строки верхнего уровня до первой метки BAT.

`MaxIncludeDepth` ограничивает рекурсивные вызовы. Значение по умолчанию — 8. Анализатор не читает один и тот же файл с теми же аргументами повторно.

Команда `load_user_lists` имеет специальную поддержку. В метке с этим именем во внешнем скрипте анализатор читает следующие операции:

```bat
echo content > path\file.txt
echo content >> path\file.txt
```

Если целевой файл не существует, анализатор собирает его содержимое в памяти и возвращает его в `GeneratedFiles`. Исходная папка не изменяется. Анализатор игнорирует файл вне исходной папки и добавляет предупреждение.

Это специальная статическая модель, а не общий интерпретатор BAT. Анализатор не воспроизводит другие способы создания файлов.

### Конфигурации TXT и файлы ответов

Конфигурация TXT содержит:

- комментарии, которые начинаются с `#`;
- строки с параметрами. Анализатор объединяет их через пробел.

Анализатор знает следующие метаданные:

```text
# BuiltinVersion: 2.11
# Preset: Config name
# ActivePreset: Config name
```

Строка версии также может иметь формы `Built-in version` или `Builtin Version`, с `:` или `=`. `BuiltinVersion` означает поколение winws2 и также задаёт версию цели. Если в файле нет метаданных имени, анализатор использует имя файла.

Анализатор считает ссылку `@file.txt` файлом ответов, только если:

1. файл существует;
2. расширение — `.txt`;
3. одна из первых 64 строк содержит `BuiltinVersion` или начинается с `--`.

Если файл ответов не существует, анализатор добавляет ошибку `INCLUDED_CONFIG_NOT_FOUND`.

Содержимое файла ответов заменяет всю строку параметров. Если в строке рядом с `@file.txt` были другие аргументы, анализатор игнорирует их и добавляет предупреждение `CONFIG_INCLUDE_IGNORES_OTHER_ARGUMENTS`.

`MaxIncludeDepth` (по умолчанию 8) ограничивает глубину включений. Анализатор хранит стек активных файлов, чтобы находить циклы.

### Поколение Zapret

Анализатор определяет поколение в следующем порядке:

1. `BuiltinVersion` означает winws2.
2. Параметры winws2 означают winws2. Это параметры `--lua-init`, `--lua-desync`, `--blob`, `--out-range`, `--ctrack-*` и `--wf-tcp-out`, `--wf-tcp-in`, `--wf-udp-out`, `--wf-udp-in`.
3. `--dpi-desync` или старые `--wf-tcp` и `--wf-udp` означают winws1.
4. Если в файле TXT нет явных признаков, анализатор использует `DefaultTextConfigGeneration`.

Фасад устанавливает значение по умолчанию равным поколению выбранной цели. При прямом вызове `ZapretConfigImportService` значение по умолчанию — winws2. Значение `null` отключает значение по умолчанию.

Если файл BAT запускает одно поколение, а параметры или включённый TXT явно относятся к другому поколению, импорт завершается ошибкой `GENERATION_MISMATCH`.

### Версия

Для winws2 анализатор выбирает версию в следующем порядке:

1. значение `# BuiltinVersion`, если оно есть;
2. `CurrentVersionResolver` из `ZapretConfigImportOptions`;
3. `CurrentVersion` установленного Zapret 2 в БД Магазина;
4. `%CURRENT%`.

Для winws1 анализатор не использует `BuiltinVersion`. Ошибки резолвера или БД не блокируют импорт.

### Переменные Zapret в ConfigItem

#### Обычные `variables`

Используемая переменная без альтернатив становится строкой в `variables`:

```text
%LISTS%=$GETCURRENTDIR()/lists/list-general.txt
```

#### `commaVars` и `availableCommaVarsValues`

Переменная с альтернативами попадает в `commaVars`. Закомментированные значения `set` и значения из статического обхода становятся списком в `availableCommaVarsValues`.

Строка запуска сохраняет ссылку `%NAME%`. Поэтому пользователь может изменить значение в виджете UI и не должен редактировать всю строку.

#### Неизвестные переменные

Анализатор добавляет каждую неизвестную `%NAME%` из строки запуска, основных значений или альтернатив так:

```json
"commaVars": {
  "NAME": "$EMPTY"
}
```

Формы `%~...%` не включаются. Для неизвестной переменной, которая нужна строке запуска или используемой переменной, анализатор также добавляет предупреждение `UNRESOLVED_BATCH_VARIABLE`.

#### Условные переменные и `jparams`

Переменная может стать логическим переключателем, если её присваивает статически прочитанный вызываемый скрипт. Если анализатор видит ровно два разных непустых значения переменной, он создаёт:

- логический параметр `use<VariableName>` в `jparams`;
- условную переменную в `variables`.

Результат имеет следующий формат:

```text
%GameFilter%=$LOCALCONDITION(useGameFilter==true ? 1024-65535 $SEPARATOR 12)
```

Текущее значение переменной задаёт начальное состояние логического параметра. Анализатор удаляет из имени параметра все символы, кроме букв, цифр и `_`. При совпадении имён к имени добавляется числовой суффикс.

Если анализатор видит другое число значений, он не создаёт логический переключатель.

#### Переключатели `ACTIVE_*.bin`

Анализатор может преобразовать ссылку вида `%ROOT%ACTIVE_name.bin` в отдельную переменную, значение которой выбирает пользователь.

Анализатор выполняет следующие шаги:

1. Раскрывает папку из переменной `ROOT`.
2. Находит в папке все файлы `*.bin`, имена которых не начинаются с `ACTIVE_`. Сортирует их по имени.
3. Сравнивает SHA-256 активного файла BIN с каждым кандидатом.
4. Последний кандидат с тем же содержимым становится текущим значением.
5. Все найденные файлы BIN становятся значениями в `availableCommaVarsValues`.
6. Ссылка становится `%<selector>%`.

Ссылка не изменяется, если переменная `ROOT` неизвестна, если папка не существует или если в папке нет кандидатов. Если активный файл отсутствует или ни у одного кандидата нет того же содержимого, анализатор всё равно создаёт переключатель. Тогда текущее значение — исходный путь к файлу `ACTIVE_`.

### ConfigItem Zapret

Результат имеет следующие базовые поля:

```json
{
  "meta": "pUC:v1.0",
  "name": "name from the metadata or the file",
  "target": ["component-id", "version-or-%CURRENT%"],
  "jparams": {},
  "variables": [],
  "commaVars": {},
  "availableCommaVarsValues": [],
  "startup_string": "normalized arguments"
}
```

Анализатор заменяет каждую последовательность пробельных символов вне двойных кавычек одним пробелом. Он заменяет `%~dp0` на `$GETCURRENTDIR()/`. Он не изменяет обратные косые черты.

Анализатор Zapret сначала использует внутренний ID Zapret или Zapret 2 для поколения. Затем `ConfigImportService` заменяет его на ID выбранного компонента Магазина. Поэтому этот парсер могут использовать и другие установленные компоненты с исполняемым файлом `winws` или `winws2`.

## Внешние ресурсы

### Общий анализатор

Общий анализатор ищет ссылки со следующими расширениями:

- `.bin`;
- `.txt`;
- `.lua`;
- `.dat`;
- `.conf`;
- `.cfg`;
- `.json`.

### Анализатор Zapret

Анализатор Zapret ищет `.bin`, `.txt` и `.lua`.

Путь может быть в кавычках или без них. Анализатор удаляет префиксы `@` и `$` перед проверкой файла. Он разрешает относительный путь относительно файла, который содержит ссылку.

Анализатор добавляет существующий файл в `ReferencedFiles`. Отсутствующий файл он добавляет в `MissingReferencedFiles` и добавляет предупреждение `REFERENCED_FILE_NOT_FOUND`. Отсутствующий файл, который генерирует скрипт BAT, не попадает в `MissingReferencedFiles`.

### Стандартные библиотеки LUA компонента

Для Zapret фасад может удалить отсутствующий файл `.lua` из списка отсутствующих файлов, если:

1. путь находится внутри структуры папок импортированного файла;
2. файл с тем же относительным путём существует в папке выбранного установленного компонента;
3. конфигурация не требует импортированную копию через `$GETCURRENTDIR()/relative/path.lua`.

В этом случае фасад считает, что файл LUA поставляет компонент. Он удаляет связанное предупреждение.

## Отсутствующие файлы

Мастер требует явного решения для каждого пути в `MissingReferencedFiles` перед сохранением.

Возможны два типа решения:

1. существующий файл замены;
2. пустой файл: `ReplacementPath == null`.

`ApplyMissingFileResolutions` принимает только решения для файлов, которые есть в исходном списке отсутствующих файлов. Он нормализует пути с помощью `Path.GetFullPath`. Если выбранный файл замены не существует, он добавляет блокирующую ошибку `MISSING_FILE_REPLACEMENT_NOT_FOUND`.

### Автокорректор

`ConfigImportAutoCorrector` ищет замену в два шага:

1. Ищет файл с тем же именем в папке импортированной конфигурации. Поиск спускается максимум на 3 уровня подпапок. Он пропускает папки, которые не может открыть, и точки повторного анализа (reparse points).
2. Вызывает существующий `Autocorrector.FindAutoCorrectPath` с временным `packId`, который указывает на исходную папку.

Автокорректор не копирует и не изменяет файлы. Он только возвращает существующий путь. Он игнорирует исключения поиска, чтобы неудачное предложение не блокировало мастер.

Для файла, имя которого содержит `user` или `debug` (в любом регистре), мастер предлагает пустой файл и не ищет замену.

На странице исправлений пользователь может:

- принять найденную замену;
- выбрать другой файл;
- выбрать пустой файл;
- принять все доступные предложения кнопкой продолжения.

## Смена цели (Retarget)

Выбор компонента на карточке результата не изменяет исходный объект сразу. Перед тестом и сохранением мастер выполняет следующие шаги:

1. Применяет решения для отсутствующих файлов.
2. Вызывает `ConfigImportService.Retarget`.
3. Проверяет, что конфигурация остаётся успешной после смены цели.

### Тот же исполняемый файл

Если старая и новая цели используют один и тот же исполняемый файл, смена цели сохраняет версию из `config.target`, если она не пустая. Она заменяет ID компонента на выбранный ID.

### `winws1 -> winws2`

Это единственное преобразование между поколениями в `Retarget`.

1. Смена цели записывает исходную папку как `packId` в клон конфигурации.
2. `ConfigurationService.GetStartupParametersByConfigItem` раскрывает `variables`, `commaVars`, `jparams` и служебные функции в готовую командную строку winws1.
3. Существующий `Zapret1ToZapret2Converter` получает готовую строку.
4. Проблемы конвертера попадают в `Issues`.
5. Если преобразование успешно, преобразованная строка попадает в `startup_string`.
6. Смена цели очищает `jparams`, `variables`, `commaVars` и `availableCommaVarsValues`, потому что строка уже раскрыта.
7. Целью становится выбранный компонент winws2 и его версия.
8. Смена цели очищает временный `packId`.

Если конвертер возвращает ошибку, `Config` становится `null`, и тест и сохранение блокируются.

`Zapret1ToZapret2Converter` не входит в это дополнение. Дополнение только вызывает его и передаёт его проблемы без изменений.

### Другие сочетания исполняемых файлов

Для других сочетаний специального преобразования нет. Смена цели заменяет цель и версию и сохраняет строку запуска. UI показывает предупреждение, если определённый исполняемый файл отличается от выбранного. Это предупреждение носит информационный характер и не блокирует операцию.

Дополнение не может преобразовать `winws2 -> winws1`.

## Тест конфигурации

`MainPage` выполняет пробный запуск в следующие шаги:

1. Останавливает предыдущий активный тест.
2. Применяет решения для отсутствующих файлов.
3. Выполняет смену цели.
4. Временно устанавливает `packId` в папку исходного файла.
5. `ConfigurationService.GetStartupParametersByConfigItem` создаёт готовые аргументы.
6. `ConfigImportTestPlaceholder.Create` подготавливает временные зависимости.
7. Останавливает выбранный компонент, если он работает.
8. Запускает компонент через `ComponentTasksManager.CreateAndRunNewTask(componentId, arguments)`.
9. Подписывается на изменения состояния задачи.
10. Когда процесс останавливается, удаляет временные файлы.

Одновременно может работать только один тест. Повторное нажатие кнопки той же карточки останавливает тест. Когда страница закрывается или выгружается, она также останавливает процесс и освобождает временные файлы.

Если процесс останавливается сразу после запуска, тест считается неудачным.

### Временные зависимости теста

Временная папка имеет следующий шаблон:

```text
%TEMP%\CDPIUI\ConfigImportPlaceholders\<GUID>\
```

Если хотя бы одно отсутствующее значение должно быть пустым, класс создаёт один общий пустой файл:

```text
empty.bin
```

Если пользователь выбрал существующую замену, тест использует её исходный путь. Класс записывает генерируемые файлы в UTF-8 без BOM в подпапку `generated` с именами вида `0000_<original-name>`.

Класс заменяет в готовых аргументах следующие формы:

- ожидаемый абсолютный путь;
- форму `$GETCURRENTDIR()/relative/path`.

В этих формах допустимо смешение `/` и `\`. Класс не обрабатывает формы `%~dp0relative`, `./relative` и простой `relative/path`, если `ConfigurationService` не раскрыл их ранее.

`Dispose` удаляет только папку внутри разрешённого корня `ConfigImportPlaceholders`. Очистка выполняется по возможности (best effort).

## Сохранение конфигурации и ресурсов

`ConfigImportInstaller.InstallAsync` принимает только успешный результат, непустое имя и явное решение для каждого отсутствующего файла.

Для результата `.cdpiconfig` (задан `SharedPackage`) установщик вызывает `ConfigShareService.InstallAsync` с отредактированной конфигурацией. Остальная часть этого раздела относится к другим форматам.

### Корень сохранения

Установщик сохраняет конфигурацию в локальный служебный набор:

```text
Store\Items\LocalUserStorage\
```

Точный абсолютный путь возвращает `ConfigurationService.GetItemFolderFromPackId(SharedConstants.LocalUserItemsId)`.

Установщик сохраняет ресурсы по типам:

```text
LocalUserStorage\List\Converted\<importId>\...
LocalUserStorage\Bin\Converted\<importId>\...
LocalUserStorage\Lua\Converted\<importId>\...
```

Категорию задаёт расширение:

- `.txt` -> `List`;
- `.lua` -> `Lua`;
- все остальные ресурсы -> `Bin`.

`importId` — это время UTC `yyyyMMddHHmmss`, символ `_` и часть GUID. Установщик обрезает строку до 24 символов.

### Относительные пути

Установщик сохраняет исходные подпапки ресурса. Он удаляет одну стандартную верхнюю папку, чтобы категория не повторялась:

- для `List`: `list` или `lists`;
- для `Lua`: `lua`;
- для `Bin`: `bin` или `fake`.

Пример:

```text
original path: lists\ipset-exclude.txt
saved path: List\Converted\<importId>\ipset-exclude.txt
```

Если внешний ресурс находится вне папки исходной конфигурации, установщик использует только имя файла. Это не позволяет записать файл вне целевой папки: установщик повторно проверяет конечное место назначения.

Если два сохраняемых относительных пути совпадают, установщик добавляет к имени второго файла первые восемь шестнадцатеричных символов SHA-256 ожидаемого абсолютного пути.

### Источники ресурсов

Установщик создаёт ресурс одним из трёх способов:

1. Копирует существующий `ReferencedFile` без перезаписи.
2. Записывает `GeneratedFile` в UTF-8 без BOM.
3. Для отсутствующего файла с решением `null` создаёт пустой файл. Для отсутствующего файла с заменой копирует выбранный файл.

### Изменение путей

Перед сохранением установщик создаёт глубокий клон конфигурации через JSON. Он изменяет пути в:

- `startup_string`;
- каждом элементе `variables`;
- каждом значении `commaVars`;
- каждом значении в `availableCommaVarsValues`.

Целевой формат:

```text
$GETCURRENTDIR()/List/Converted/<importId>/file.txt
$GETCURRENTDIR()/Bin/Converted/<importId>/file.bin
$GETCURRENTDIR()/Lua/Converted/<importId>/file.lua
```

Установщик знает следующие формы:

- абсолютный исходный путь;
- `$GETCURRENTDIR()/source/path`;
- `%~dp0source/path` для сопоставлений папок;
- относительный `source/path`;
- `./source/path` и `.\source\path`;
- необязательный префикс `@` для ссылки на отдельный файл;
- смешанные разделители `/` и `\`.

Сначала установщик выполняет сопоставления папок. Сопоставление применяется, только когда одна исходная папка соответствует ровно одной сохранённой папке. Затем установщик изменяет пути отдельных файлов.

### Транзакционное сохранение

Для каждой категории установщик сначала создаёт промежуточную папку:

```text
<Category>\Converted\.<importId>.tmp
```

Установщик выполняет следующие шаги:

1. Создаёт промежуточные папки.
2. Записывает или копирует все ресурсы.
3. Подготавливает клон конфигурации и изменяет пути.
4. Перемещает промежуточные папки в `<importId>`.
5. Сохраняет JSON через `ConfigurationService.SaveConfigItem`.
6. Если происходит ошибка, удаляет созданные им папки и JSON, если он существует.

Удаление ограничено проверенным корнем `Converted` категории. Откат выполняется по возможности (best effort). Установщик никогда не удаляет исходные файлы.

### Имя файла конфигурации

Установщик записывает отображаемое имя в `name` и `not_converted_name`.

Имя JSON подчиняется следующим правилам:

1. Буквы Unicode, цифры, `_`, `.` и `-` сохраняются.
2. Каждый другой символ, в том числе каждый пробельный символ, становится `_`.
3. Установщик удаляет `_` и `.` в начале и в конце.
4. Пустой результат становится `Imported_Config`.
5. При совпадении имён добавляется `_2`, `_3` и так далее.

Установщик сохраняет конфигурацию с `packId = LocalUserStorage` через `SaveConfigItem`. JSON не обязан содержать `packId`.

После успешного сохранения UI вызывает `ReInitConfigs()` для выбранного компонента.

## Мастер импорта

### Шаг 1. Выбор

Диалог выбора файлов позволяет выбрать несколько файлов `.txt`, `.bat`, `.cmd`, `.json` и `.cdpiconfig`. Пользователь также может перетащить файлы на страницу настроек компонента (`ViewComponentSettingsPage`). Тогда страница открывает окно импорта с этими файлами и ID компонента. Один перетащенный файл `.cdpiconfig` может вместо этого попасть в диалог ConfigShare. Имя конфигурации по умолчанию — имя файла без расширения. Для пакета `.cdpiconfig` имя по умолчанию — имя из манифеста.

### Шаг 2. Анализ

Фоновая задача обрабатывает файлы по одному. Для каждого файла мастер выполняет следующие шаги:

1. Находит подходящую цель.
2. Выполняет импорт.
3. Создаёт отдельную карточку результата.
4. Показывает успех, предупреждение или ошибку.

Для пакета `.cdpiconfig` с отсутствующим компонентом мастер предлагает установщик компонента из Магазина.

Всплывающая панель **Подробнее** показывает проблемы в формате `[CODE] [line] message`.

### Шаг 3. Отсутствующие файлы

Мастер показывает этот шаг, только если в успешных результатах есть отсутствующие ресурсы. Пользователь может продолжить, когда он принял решение для каждого файла или когда для каждого оставшегося файла есть предложение.

### Шаг 4. Результаты

Каждая карточка позволяет пользователю:

- изменить имя;
- выбрать установленный компонент;
- увидеть предупреждение о другом исполняемом файле;
- увидеть проблемы;
- запустить и остановить тест;
- сохранить карточку.

Кнопка **Сохранить все** по очереди сохраняет все карточки с `CanSave == true`. Мастер удаляет сохранённые карточки из списка. Карточки с ошибкой остаются в списке.

## Проблемы

Каждая проблема имеет:

- `Severity`: `Warning` или `Error`;
- стабильную строку `Code`;
- техническое сообщение `Message`;
- необязательный `SourcePath`;
- необязательный `LineNumber`.

### Общие коды

| Код | Уровень | Условие |
|---|---|---|
| `FILE_NOT_FOUND` | Error | Исходный файл не существует |
| `TARGET_REQUIRED` | Error | ID компонента не выбран |
| `EXECUTABLE_REQUIRED` | Error | В записи цели нет исполняемого файла |
| `UNSUPPORTED_FORMAT` | Error | Выбранный анализатор не поддерживает расширение |
| `IMPORT_FAILED` | Error | Во время анализа произошло необработанное исключение |
| `EXECUTABLE_LAUNCH_NOT_FOUND` | Error | В общем файле BAT или CMD нет запуска выбранного исполняемого файла |
| `MULTIPLE_EXECUTABLE_LAUNCHES` | Error | В файле больше одного запуска выбранного исполняемого файла |
| `TEXT_CONFIG_EMPTY` | Error | В общем файле TXT нет аргументов |
| `JSON_CONFIG_INVALID` | Error | JSON не является поддерживаемым `ConfigItem` или `OldConfigItem` |
| `EXECUTABLE_MISMATCH` | Error | Анализ Zapret нашёл поколение, которое отличается от цели |
| `UNRESOLVED_VARIABLE` | Warning | Общий анализатор не может разрешить переменную BAT |
| `REFERENCED_FILE_NOT_FOUND` | Warning | Внешний ресурс отсутствует |
| `REFERENCED_FILE_OUTSIDE_SOURCE` | Warning | Конфигурация использует файл вне папки импортируемого файла. Импорт копирует этот файл в пресет |
| `INVALID_RESOURCE_PATH` | Warning | Анализатор не может нормализовать путь ресурса |
| `MISSING_FILE_REPLACEMENT_NOT_FOUND` | Error | Замена, которую выбрал пользователь, не существует |

Для файла `.cdpiconfig` код проблемы — это код `ConfigShareException`, например `SHARE_IMPORT_FAILED`.

### Коды анализатора Zapret

| Код | Уровень | Условие |
|---|---|---|
| `BATCH_READ_FAILED` | Error | Файл BAT или CMD нельзя прочитать |
| `TEXT_CONFIG_READ_FAILED` | Error | Файл TXT нельзя прочитать |
| `WINWS_LAUNCH_NOT_FOUND` | Error | В файле BAT или CMD нет поддерживаемого запуска winws или winws2 |
| `MULTIPLE_WINWS_LAUNCHES` | Error | В файле больше одного запуска winws или winws2 |
| `TEXT_CONFIG_HAS_NO_OPTIONS` | Error | В файле TXT нет параметров `--...` и нет файла ответов |
| `CONFIG_GENERATION_UNKNOWN` | Error | Поколение TXT неизвестно, а значение по умолчанию отключено |
| `GENERATION_MISMATCH` | Error | Исполняемый файл и параметры относятся к разным поколениям |
| `INCLUDED_CONFIG_NOT_FOUND` | Error | Указанный файл ответов не существует |
| `INCLUDE_CYCLE` | Error | Включения TXT образуют цикл |
| `INCLUDE_DEPTH_EXCEEDED` | Error | Глубина включений превышает предел |
| `CONFIG_INCLUDE_IGNORES_OTHER_ARGUMENTS` | Warning | Анализатор проигнорировал аргументы рядом с файлом ответов |
| `CALLED_SCRIPT_READ_FAILED` | Warning | Вызываемый файл BAT или CMD существует, но его нельзя прочитать |
| `UNRESOLVED_BATCH_VARIABLE` | Warning | Используемую переменную BAT нельзя разрешить |
| `GENERATED_FILE_OUTSIDE_SOURCE` | Warning | Генерируемый файл находится вне исходной папки |
| `REFERENCED_FILE_NOT_FOUND` | Warning | Файл BIN, TXT или LUA отсутствует |
| `REFERENCED_FILE_OUTSIDE_SOURCE` | Warning | Конфигурация использует файл вне папки импортируемого файла. Импорт копирует этот файл в пресет |

### Коды установщика

| Код | Условие |
|---|---|
| `IMPORT_RESULT_INVALID` | Анализ или смена цели не успешны |
| `IMPORT_NAME_REQUIRED` | Имя конфигурации пустое |
| `IMPORT_MISSING_FILE_RESOLUTION_REQUIRED` | Для отсутствующего файла нет решения |
| `IMPORT_INSTALL_FAILED: ...` | Во время записи, копирования, изменения пути или сохранения произошло исключение |
| `<ConfigShare code>: ...` | `ConfigShareService.InstallAsync` завершился ошибкой для пакета `.cdpiconfig` |

`ConfigurationService.SaveConfigItem` может вернуть собственный код ошибки. Установщик передаёт его вызывающему коду без изменений. Установщик также добавляет коды `Zapret1ToZapret2Converter` в `Issues` без изменений. Полный список этих кодов определяет реализация конвертера.

## Пример прямого вызова

```csharp
using CDPIUI.AddOns.ConfigImport;

var service = new ConfigImportService();
var target = new ConfigImportTarget(
    ComponentId: "CSZTBN062",
    DisplayName: "Zapret 2",
    Executable: "winws2",
    Version: "2.11",
    Directory: @"C:\path\to\zapret2");

ConfigImportResult analyzed = service.Import(
    @"C:\configs\service.bat",
    target);

if (!analyzed.IsSuccessful)
{
    foreach (ConfigImportIssue issue in analyzed.Issues)
        Console.WriteLine($"{issue.Severity}: [{issue.Code}] {issue.Message}");
    return;
}

var resolutions = analyzed.MissingReferencedFiles.Select(path =>
    new ConfigImportMissingFileResolution(path, ReplacementPath: null));

ConfigImportResult resolved = service.ApplyMissingFileResolutions(analyzed, resolutions);
ConfigImportResult retargeted = service.Retarget(resolved, target);

var installer = new ConfigImportInstaller();
ConfigImportInstallResult installed = await installer.InstallAsync(
    retargeted,
    "Imported Zapret Config");
```

ВНИМАНИЕ: Попросите пользователя подтвердить `ReplacementPath: null`, прежде чем использовать его для многих файлов. Анализатор не считает отсутствующий файл разрешённым автоматически.

## Пример преобразования переменной BAT

Исходный фрагмент:

```bat
set "LISTS=%~dp0lists\list-general.txt"
rem set "LISTS=%~dp0lists\list-alt.txt"
winws2.exe --hostlist=%LISTS% --lua-desync=fake
```

Логическая часть результата до сохранения:

```json
{
  "commaVars": {
    "LISTS": "$GETCURRENTDIR()/lists\\list-general.txt"
  },
  "availableCommaVarsValues": [
    {
      "VarName": "LISTS",
      "CurrentValueIndex": 0,
      "Values": [
        "$GETCURRENTDIR()/lists\\list-general.txt",
        "$GETCURRENTDIR()/lists\\list-alt.txt"
      ]
    }
  ],
  "startup_string": "--hostlist=%LISTS% --lua-desync=fake"
}
```

После сохранения пути обоих значений указывают на `List/Converted/<importId>/...`.

## Ограничения статического анализа

Дополнение не является интерпретатором `cmd.exe`. Оно обрабатывает следующие конструкции частично или не обрабатывает совсем:

- ветви `if` и циклы `for`;
- вычисления `set /a` и сложные подстановки `%VAR:...%`;
- имена переменных и команд, которые скрипт создаёт во время выполнения;
- `goto` и общий поток управления файлов BAT;
- команды, которые создают файлы иначе, чем поддерживаемые `echo >` и `echo >>` в `load_user_lists`;
- исполняемый файл, который запускает обёртка, функция или неизвестная конструкция;
- несколько возможных запусков с выбором во время выполнения. Дополнение намеренно считает их неоднозначными;
- файлы ответов в нестандартном формате;
- ресурсы с расширением, которого нет в списке известных.

Также учитывайте следующие ограничения:

- Значения, которые зависят от текущего окружения ОС, могут давать разные результаты на разных компьютерах.
- Дополнение не проверяет совместимость произвольного компонента, кроме специальных проверок Zapret.
- Дополнение не может преобразовать winws2 в winws1.
- Тест не изолирует процесс компонента и не воспроизводит полный исходный BAT.
- Временная замена путей в тесте знает меньше относительных форм, чем установщик.

Неизвестная переменная обычно сохраняется: она становится редактируемой `commaVar` со значением `$EMPTY`. Поэтому пользователь может дополнить конфигурацию вручную.

## Правила расширения

### Новый общий компонент

Если его файл BAT или CMD запускает исполняемый файл напрямую обычной командной строкой, отдельный парсер не нужен. Выполните следующие шаги:

1. Добавьте или установите компонент Магазина с правильными значениями `Id`, `Directory`, `Executable` и `CurrentVersion`.
2. При необходимости расширьте список расширений ресурсов.
3. Проверьте, что определение исполняемого файла и сохранение путей работают.

### Специальный синтаксис

Если компонент использует собственный формат включений, условные переменные или генерируемые ресурсы, выполните следующие шаги:

1. Оставьте `ConfigImportService` фасадом.
2. Добавьте отдельный статический анализатор без зависимостей от UI.
3. Преобразуйте специальный результат в `ConfigImportResult`.
4. Не запускайте исходный скрипт.
5. Возвращайте стабильные коды проблем.
6. Явно опишите правила поколения, версии и несовместимости.
7. Поместите зависимости в `ReferencedFiles`, `MissingReferencedFiles` и `GeneratedFiles`.
8. Проверьте, что тест и сохранение изменяют пути одинаково.
9. Добавьте автоматические тесты с реальными наборами конфигураций в `CDPIUI.Tests`.

### Изменение структуры хранения

Изменяйте структуру `List|Bin|Lua/Converted/<importId>` только вместе с:

- `GetResourceCategory`;
- `GetOrganizedRelativePath`;
- `BuildResources`;
- `RewriteResources`;
- тестами, которые загружают конфигурацию через `ConfigurationService`;
- логикой удаления и отката, которая ограничивает разрешённые корни.

## Инварианты

Сохраняйте следующие свойства при всех изменениях:

1. Анализ входного файла BAT или CMD не запускает его.
2. Дополнение не изменяет и не удаляет исходные файлы.
3. Отсутствующий файл не считается разрешённым без явного `ConfigImportMissingFileResolution`.
4. Каждый импорт получает отдельную папку ресурсов.
5. После сохранения пути конфигурации указывают на фактическую категорию `List`, `Bin` или `Lua`.
6. Запись не может выйти за пределы промежуточной папки или папки назначения.
7. Неудачное сохранение конфигурации запускает откат созданных ресурсов.
8. `winws1 -> winws2` преобразует готовую раскрытую строку. Парсер Zapret не смешивает поколения.
9. Нативная конфигурация winws2 сохраняется без преобразования синтаксиса.
10. Тест удаляет временные файлы после остановки процесса или закрытия страницы.

## Тесты

В `CDPIUI.Tests/AddOns` есть тесты для этого дополнения:

- `ConfigImportServiceTests.cs` проверяет `ConfigImportService.TryParseSet`;
- `ZapretConfigImportServiceTests.cs` проверяет `TrimShellTail` и `ExpandFileModifiers`.

`CDPIUI.Tests/Core/BatchFileEncodingTests.cs` проверяет определение кодировки.

Минимальный набор ручных проверок для изменения включает:

1. простой файл BAT для общего компонента;
2. файл BAT с продолжениями строк через каретку;
3. файл BAT с одним запуском и с несколькими запусками;
4. файл BAT winws1 и смену цели на winws2;
5. нативный файл BAT winws2;
6. файл TXT с `# BuiltinVersion`;
7. файл BAT, который ссылается только на файл ответов TXT;
8. `service.bat` с переменными, диспетчеризацией и `load_user_lists`;
9. `ACTIVE_*.bin` с тем же SHA-256;
10. известный, отсутствующий, заменённый и пустой ресурс каждого типа;
11. пути `list/lists`, `bin/fake`, `lua`, абсолютные пути и `$GETCURRENTDIR()`;
12. пробный запуск с отсутствующими и генерируемыми файлами;
13. сохранение двух конфигураций с одинаковым именем;
14. искусственную ошибку `SaveConfigItem` для проверки отката;
15. текущий и старый формат JSON.

Успешная сборка подтверждает только компиляцию. Также проверьте фактические аргументы процесса, сохранённый JSON, расположение ресурсов и запуск конфигурации с обычной страницы компонента.
