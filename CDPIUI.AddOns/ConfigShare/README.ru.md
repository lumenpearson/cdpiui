# ConfigShare

Файл `.cdpiconfig` — это ZIP-архив с одним пресетом и ресурсами, которые использует пресет. `ConfigShareService` экспортирует, проверяет, распаковывает и устанавливает такие архивы. `ConfigImportService` и `ConfigImportInstaller` передают этот формат в `ConfigShareService`.

Архив не содержит скриптов, и служба не выполняет код из него.

## Формат v1

`manifest.json` содержит `Version`, `Name`, `Developer`, `Config` (`ConfigItem`) и `Resources`. У каждого ресурса есть `Path`, `Length`, `Sha256` и `RewriteReferences`. Ресурсы лежат в папке `resources/`. Переносимая ссылка имеет вид `share://resources/...`.

Экспорт раскладывает ресурсы по таким папкам:

| Источник файла | Путь в архиве |
|---|---|
| Папка комплекта пресетов | `resources/preset/...` |
| Папка компонента | `resources/component/...` |
| Другие места | `resources/external/<volume hash>/...` |

Список файлов берётся только из `ConfigItem.UsedFiles`. Экспорт определяет каждый путь через `ConfigItem.ResolveFilePath`. Для этого он использует папку компонента и папку комплекта пресетов. ConfigShare упаковывает только этот список и изменяет соответствующие ссылки в пресете. Файлы, в том числе библиотеки компонента, он копирует без изменений. ConfigShare не разбирает Lua и не ищет другие зависимости.

`UsedFiles` не содержит цель `--debug`, поэтому экспорт её не упаковывает. Если файла из `UsedFiles` нет, экспорт завершается ошибкой `SHARE_FILE_MISSING`. Исключение: если нет списка для `--hostlist-auto` или `--hostlist-auto-debug`, экспорт упаковывает вместо него пустой файл. Экспорт не создаёт файл в комплекте пресетов. Этот список компонент создаёт во время работы.

## Ограничения и проверки

| Объект | Ограничение |
|---|---:|
| Записи в архиве | 4096, включая `manifest.json` |
| Ресурсы в экспорте | 4095 |
| Размер без сжатия, общий и для одной записи | 512 МиБ |
| `manifest.json` | 4 МиБ |
| Коэффициент сжатия записи больше 1 МиБ | 200 |

Перед установкой модуль чтения проверяет:

- версию формата (только `1`);
- что имя, разработчик, `target[0]` и `startup_string` не пусты;
- что в архиве есть ровно записи из манифеста и `manifest.json`;
- повторяющиеся имена записей (сравнение без учёта регистра);
- заявленный размер и SHA-256 каждого ресурса;
- количество записей, общий размер и коэффициент сжатия;
- безопасность относительных путей.

Безопасный путь начинается с `resources/` и использует только `/`. В нём нет `:`, нет частей `.` или `..`, нет частей, которые заканчиваются точкой или пробелом, нет недопустимых в именах файлов символов и нет зарезервированных имён устройств, таких как `CON` или `LPT1`.

Архив не может содержать ссылки файловой системы. Модуль чтения отклоняет записи — символические ссылки. `SafeDestination` также отклоняет папку назначения, которая содержит точку повторного анализа (reparse point).

## Параметры, которые записывают файлы

Трей запускает компоненты с правами администратора. Поэтому общий пресет не должен записывать файлы за пределами своего пакета. После того как модуль чтения заменит ссылки `share://`, `EnsureNoOutsideWrites` проверяет каждый текст конфигурации. Он ищет такие параметры:

- `--debug=@<file>` (`--debug` с другими значениями не записывает файл);
- `--wf-save`;
- `--hostlist-auto`;
- `--hostlist-auto-debug`.

Значение такого параметра должно быть абсолютным путём в папке распакованного пакета. Иначе модуль чтения завершается ошибкой `SHARE_UNSAFE_OPTION`. Относительный путь тоже отклоняется.

Экспорт выполняет ту же проверку после замены ссылок. Поэтому экспорт завершается ошибкой `SHARE_UNSAFE_OPTION` для пресета, который отклонил бы модуль чтения.

`BlockCheckReportImportService` использует ту же проверку для строки пресета из импортированного отчёта BlockCheck2. См. [BlockCheck2/README.ru.md](../BlockCheck2/README.ru.md).

## Жизненный цикл

`ExportAsync` и `ReadAsync` возвращают `ConfigSharePackage`, который владеет своей временной папкой. Освободите (Dispose) пакет после того, как скопируете экспортированный файл, или после того, как импорт завершён или отменён.

Перед отправкой через общий доступ Windows вызовите `RetainForSystemShare`. Метод записывает файл-маркер `.retain-for-system-share`, и тогда `Dispose` сохраняет папку. Когда открывается следующий диалог экспорта, `CleanupPreviousSystemShares` удаляет помеченные папки. Это происходит и после перезапуска приложения. Очистка не затрагивает другие импорты и экспорты, которые ещё выполняются.

Временные папки находятся в `TempFiles`. Их имена создаёт `FileSystemService.GetNewTempFileName`, и они содержат `ConfigShare_` и GUID. Поэтому имена не пересекаются.

`InstallAsync` помещает ресурсы в уникальную папку `Shared/<GUID>` в комплекте назначения. Одновременно выполняется только одна установка. Назначением может быть:

- `LocalUserStorage` (по умолчанию);
- существующий комплект с ID в виде GUID;
- новый комплект с ID в виде GUID. Служба создаёт папку с `init.json` и регистрирует элемент `configlist` в базе данных Магазина.

ID комплектов Магазина никогда не подходят как назначение (`SHARE_DESTINATION_INVALID`). Имя файла конфигурации — `preset_<name>_<8 hex characters>.json`. Если возникает ошибка, служба удаляет только файлы и папки, которые создала эта установка. Повторный импорт того же пакета создаёт новый пресет. Он никогда не перезаписывает существующий пресет или ресурс.

Зависимости, о которых не сообщает `UsedFiles`, нужно прикрепить к пресету как явные ресурсы.

## UI

| Точка входа | Назначение |
|---|---|
| `ConfigSelector` (`CDPIUI/Controls/ComponentSettings`) | Открывает диалог экспорта через `ConfigShareUI.ShowExportAsync` |
| `ConfigShareExportContentDialog`, `ConfigShareMessageContentDialog` (`CDPIUI/Controls/Dialogs/ConfigShare/*.xaml`) | Разметка экспорта и сообщений. Файлы code-behind обрабатывают действия и изменения состояния. |
| `ConfigShareImportDialog` (`CDPIUI/Windows/Messages`) | Открывается, когда пользователь открывает файл `.cdpiconfig` |
| Мастер ConfigImport | Показывает свои обычные шаги просмотра, проверки и сохранения для файлов `.cdpiconfig` |
| `WindowsPresetShare` (`CDPIUI/Helper/AddOns/ConfigShare`) | Общий доступ Windows через [per-window desktop interop](https://learn.microsoft.com/windows/apps/develop/ui/display-ui-objects) |

Если нужного компонента нет, обе точки входа импорта предлагают установщик компонента из Магазина (`ConfigShareUI.OfferComponentInstallAsync`). Zapret Legacy доступен, когда установлен Zapret2. В этом случае мастер использует существующее преобразование из Legacy в Zapret2.

## Тесты

`CDPIUI.Tests/AddOns/ConfigShareWriteOptionsTests.cs` проверяет `EnsureNoOutsideWrites`. Тест проверяет, что запись файлов за пределами пакета отклоняется, а запись внутри пакета и простой `--debug` принимаются.

В решении нет отдельного тестового проекта для полного цикла экспорта и импорта, зависимостей, мест назначения, повреждённых архивов и очистки.
