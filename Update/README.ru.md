# Update

`Update.exe` — это инструмент WinForms на .NET 8. Он устанавливает патч приложения
(`.cdpipatch`) в папку установки. Затем он снова запускает трей.

Как и трей, `Update.exe` — это один файл, зависящий от среды выполнения (framework-dependent). Он
использует .NET 8 Desktop Runtime, которую использует и трей. Инструмент заменяет файлы приложения
во время работы. Поэтому он не должен загружать DLL из папки установки. Один файл содержит весь
код инструмента. См. [Сборка](#сборка).

`Update.exe` не может заменить сам себя, пока работает. Поэтому патч содержит новую программу обновления под именем
`_Update.exe`. При следующем запуске трей переименовывает `_Update.exe` в `Update.exe`
(`CDPIUI.TrayIcon/Program.cs`, `.github/scripts/make_patch.ps1`).

## Запуск

`Update.exe` запускает только трей, работающий с правами администратора. Последовательность такая:

1. Главное окно (GUI) отправляет сообщение `BeginApplicationUpdate` с путём к подготовленному патчу
   (`CDPIUI.Core/Features/ApplicationUpdate.cs`).
2. Трей получает сообщение (`CDPIUI.TrayIcon/Helper/Basic/CommandsHandler.cs`) и вызывает
   `Utils.StartUpdate` (`CDPIUI.TrayIcon/Helper/Utils.cs`).
3. Трей копирует пакет в `<install>\.staging\<GUID>\`.
4. Трей проверяет подписанный каталог каждого слоя (`CDPIUI.TrayIcon/Helper/PackageStaging.cs`).
5. Трей запускает `Update.exe` с такой командной строкой:

```
Update.exe --directory-to-zip "<staged .cdpipatch>" --destination-directory "<install folder>"
```

Полная процедура проверки описана в [документации по CI и релизам](../.github/RELEASES.ru.md#how-the-application-applies-a-patch).

Замечания об аргументах (`Update/Program.cs`):

- `--directory-to-zip` — это путь к ZIP-пакету, а не к папке.
- Инструмент удаляет символы `"` в начале и в конце каждого значения. Путь в кавычках, который заканчивается на `\`, даёт лишний `"` в конце.
- Если одного из двух аргументов нет, инструмент показывает информационное сообщение и завершается.

У проекта нет своего манифеста. .NET SDK встраивает манифест по умолчанию (`asInvoker`). Поэтому `Update.exe` получает права трея.

## Процедура

Вся логика находится в `Update/InstallHelper.cs`. Процедура начинается, когда открывается окно.

1. **Остановка приложения.**
   - Инструмент устанавливает событие `Global\CDPIUI_TrayShutdown`. Тогда трей завершается так же, как из своего меню: он останавливает компоненты и восстанавливает настройки прокси.
   - Инструмент ждёт трей не более 20 с.
   - Инструмент останавливает все оставшиеся процессы `goodbyeDPI`, `CDPIUI` и `CDPIUI_TrayIcon` (`Process.Kill`).
   - Инструмент ждёт не более 10 с для каждого имени процесса. Если процесс продолжает работать, инструмент не изменяет файлы.
2. **Подготовка файлов.**
   - Инструмент удаляет старые папки `<install>\.update-staging` и `<install>\.update-backup`.
   - Перед распаковкой файла инструмент проверяет ограничения архива, что и трей (`ArchivePaths.EnsureWithinLimits`): не более 20000 записей, не более 1 ГиБ данных и коэффициент сжатия не более 200 для записи от 1 МиБ. Если архив не укладывается в ограничения, инструмент прерывает обновление. Трей делает эту проверку до запуска инструмента. Инструмент делает её снова, потому что пакет может попасть к инструменту другим путём.
   - Инструмент распаковывает пакет в новую папку `.update-staging`.
   - Инструмент прерывает обновление, если запись даёт больше данных, чем указано в её заголовке (`ArchivePaths.ExtractToFileBounded`).
   - Инструмент по порядку читает папки архива `layers/0/`, `layers/1/`, ... Приложение создаёт пакеты с такими папками.
   - Если в архиве нет папок `layers/`, инструмент читает папку `CDPIUI/`. Она есть в опубликованном патче.
   - Файл из более позднего слоя заменяет тот же файл из более раннего слоя.
   - Инструмент прерывает обновление, если у записи абсолютный путь, есть `:` или путь вне целевой папки.
   - Инструмент прерывает обновление, если архив не содержит файлов.
3. **Применение файлов.**
   - Инструмент перемещает каждый подготовленный файл в папку установки.
   - Перед этим инструмент перемещает существующий файл по тому же относительному пути в `<install>\.update-backup`.
   - Инструмент не удаляет установленные файлы. Патч разностный: он содержит только изменённые файлы. Поэтому файл, которого нет в патче, остаётся в папке установки.
4. **Откат после ошибки.**
   - Если перемещение завершается с ошибкой, инструмент восстанавливает применённые файлы из резервной папки в обратном порядке.
   - Если восстановление неполное, статус становится `NoOldVersion`.
   - В этом случае сообщение об ошибке просит пользователя заново установить приложение. Инструмент сохраняет резервную папку для ручного восстановления.
   - Инструмент не запускает приложение. Окно закрывается после того, как пользователь закроет сообщение об ошибке.
5. **Завершение обновления.**
   - Инструмент удаляет промежуточную и резервную папки.
   - Инструмент удаляет файл `<install>\.update-manifest`, если он есть. Этот файл записывали более ранние версии инструмента.
   - Инструмент запускает трей.

### Пропускаемые файлы

- Инструмент никогда не переносит файл `catalog.cat` из патча. Каталог патча перечисляет только файлы этого патча. Поэтому после следующего патча он не соответствует папке установки.
- Инструмент не переносит `Update.exe`, если `Update.exe` уже есть в целевой папке. Патч содержит новую программу обновления под именем `_Update.exe`.

## Перезапуск трея

Инструмент запускает `CDPIUI_TrayIcon.exe` из папки установки с одним из следующих аргументов:

| Аргумент | Условие |
|----------|-----------|
| `--after-patching` | Обновление прошло успешно. |
| `--after-failed-update` | Инструмент не применил обновление. Предыдущие файлы сохранены или восстановлены. Причины: приложение не остановилось, пакета нет, распаковка или применение завершились с ошибкой. |

Поведение трея (`CDPIUI.TrayIcon/Program.cs`):

- С любым из аргументов трей запускает GUI от имени пользователя рабочего стола.
- С `--after-failed-update` трей показывает уведомление `UpdateFailure`.
- С `--after-patching` трей показывает то же уведомление, только если не может переименовать `_Update.exe` в `Update.exe`.

Если исполняемого файла трея нет или он не запускается, инструмент показывает сообщение об ошибке.

## Журнал

Инструмент добавляет строки в `update.log` в папке `Update.exe`, то есть в папке
установки. Каждая строка начинается с `[yyyy-MM-dd HH:mm:ss]`. Инструмент игнорирует ошибки записи журнала.

Очистка при удалении MSI удаляет `update.log`, `.update-manifest`, `.update-staging`,
`.update-backup` и другие файлы времени выполнения (`CDPIUI.TrayIcon/Helper/UninstallHelper.cs`).

## Окно

Окно `Update Assistant` (`Update/Form1.cs`, `Update/Form1.Designer.cs`) имеет фиксированный размер
и не имеет кнопок управления окном. Окно использует шрифт Microsoft Sans Serif 8,25 пт, который был
шрифтом по умолчанию в .NET Framework (`Application.SetDefaultFont` в `Update/Program.cs`). Шрифт по умолчанию в .NET 8 крупнее.
Как и раньше, окно не поддерживает масштабирование DPI (`Application.SetHighDpiMode`). Windows масштабирует его.
Тексты окна — на английском языке. Если язык интерфейса Windows — русский, они на русском языке (`Update/Strings.cs`). Строки журнала всегда на английском языке.

Окно содержит следующие элементы управления:

| Элемент | Содержимое |
|---------|---------|
| Индикатор выполнения | Идёт от 0 % до 100 % во время распаковки. Затем снова идёт от 0 % до 100 % на шаге применения. |
| Строка состояния | `Preparing...`, `Unpacking...`, `Copying files...`, `Finalizing...`, текущий файл, `Complete` или `Exception happens`. |
| Кнопка (`Cancel`) | Недоступна, пока процедура не завершится успешно или с ошибкой. Затем её текст меняется на `Close`, и она закрывает инструмент. |

Пользователь не может закрыть окно, пока идёт обновление (`FinishStatus` равен `None`). После
успешного запуска трея инструмент закрывается автоматически.

Инструмент показывает окно сообщения об ошибке в следующих случаях: откат неполный, трей не
запускается или возникает непредвиденное исключение. Поток установки передаёт ошибку в поток
UI. Окно сообщения принадлежит главному окну инструмента. Поэтому окно сообщения не может открыться позади окна.
Когда пользователь закрывает окно сообщения, инструмент завершается.

## Сборка

`Update/Update.csproj` — проект в стиле SDK: `net8.0-windows`, Windows Forms, x64, `win-x64`.
Версия (`1.1.0.0`) и другие данные сборки находятся в файле проекта.

```
dotnet publish Update/Update.csproj -c Release -p:Platform=x64 -r win-x64 --self-contained false -p:PublishSingleFile=true
```

В Linux или macOS добавьте `-p:EnableWindowsTargeting=true`. `.github/scripts/build_portable.ps1`
использует ту же команду и копирует `Update.exe` в раскладку релиза. Папка публикации должна
содержать только `Update.exe`.

Проект не ссылается на `CDPIUI.Shared`, потому что инструмент не должен загружать
`CDPIUI.Shared.dll` из папки, которую он заменяет. Он компилирует два файла `CDPIUI.Shared` как
ссылки: `Basic/Filesystem/UpdatePackageLayers.cs` и `Basic/Filesystem/ArchivePaths.cs`. Поэтому
инструмент и трей используют одно правило слоёв и одни ограничения архива. С символом
`UPDATE_TOOL` эти классы являются `internal` и находятся в пространстве имён `Update`.

## Тесты

`CDPIUI.Tests/Tools/UpdateInstallHelperTests.cs` проверяет проверку путей, ограничения архива,
порядок слоёв, правила подготовки файлов (`catalog.cat`, `Update.exe`), шаг применения и откат.
Тесты не используют окно.
