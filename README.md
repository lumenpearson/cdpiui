## Что изменилось?
**GoodbyeDPI UI** теперь **CDPI UI**. Изменилось не только название — приложение было переписано с нуля, что позволило снизить потребление оперативной памяти в фоне до 8 МБ, повысить стабильность работы приложения, сделать компонент GoodbyeDPI необязательным для установки. Помимо этого, приложение занимает всего 135 МБ на жёстком диске*.

Теперь компоненты и пресеты загружаются через Магазин — бесплатную площадку для скачивания компонентов с официального репозитория. Вы можете [добавлять свои элементы в Магазин](https://github.com/Storik4pro/CDPIUI-Store) или скачивать уже существующие.

Автоматический подбор параметров запуска теперь работает стабильнее и имеет удобный интерфейс для формирования пресета сразу для нескольких списков сайтов.

Свои пресеты теперь можно переименовывать и добавлять в стандартный селектор — больше не придётся добавлять пресеты в селектор обходными путями или каждый раз выбирать новый JSON-файл.

Теперь можно делиться пресетами! Просто нажмите [Поделиться] рядом с селектором пресета и отправьте файл другу. Открыть такой файл можно двойным кликом.

Узнайте все новые возможности по ссылке [cdpiui://AppFeatures](cdpiui://AppFeatures). *Требуется установленная последняя версия **CDPI UI***

\* — конечный вес приложения зависит от установленных из Магазина элементов и количества личных данных пользователя

### Шаги установки
1. Скачайте последнюю версию **CDPI UI** на [странице релизов](https://github.com/Storik4pro/cdpiui/releases/latest)
2. Если вы скачали `Setup.msi`, установите приложение. Если вы скачали `_portable.zip`, распакуйте архив в предпочитаемую папку
3. Откройте приложение **CDPI UI**, кликнув на исполняемый файл `CDPIUI.exe` или через ярлык в меню "Пуск"
4. Откройте Магазин через страницу [Утилиты] (или перейдите по [cdpiui://Store](cdpiui://Store))
5. Найдите и установите предпочитаемый вами компонент и набор пресетов
6. Выберите компонент и пресет по умолчанию
7. Запустите компонент, нажав на кнопку [▶️ Запустить]. При желании добавьте компонент в автозапуск системы.
8. Закройте все лишние окна приложения — теперь приложение будет работать в фоновом режиме. Нажмите на иконку в системном лотке уведомлений или ещё раз нажмите на ярлык приложения, чтобы открыть главное окно
9. Вы великолепны!

## Как устроено приложение

**CDPI UI** состоит из двух процессов, которые обмениваются сообщениями через именованный канал (pipe):

| Часть | Учётная запись | Назначение |
|---|---|---|
| Главное окно (`CDPIUI.exe`) | Текущий пользователь, без повышения прав | Окна приложения, Магазин, пресеты, дополнения и настройки |
| Трей (`CDPIUI_TrayIcon.exe`) | Администратор | Запуск и остановка компонентов, системный прокси, автозапуск, уведомления, условный запуск |

Главное окно не запускает компоненты само: оно отправляет запрос трею, а трей запускает компонент и передаёт его состояние и вывод обратно. Трей принимает команды только от главного окна приложения и запускает файлы только из папки установки и папок данных **CDPI UI**. В установке MSI новую или изменённую программу вне папки установки трей запускает, только если это подписанный элемент Магазина или если пользователь подтвердил запуск.

Ещё две утилиты работают на .NET 8, как и трей, и поставляются одним файлом каждая: `Update.exe` устанавливает обновления приложения (`.cdpipatch`), `EditHostFile.exe` изменяет файл hosts с правами администратора.

## Сборка из исходного кода

Понадобятся Windows 10 или 11 (x64), Visual Studio 2022 с нагрузками для .NET Desktop и WinUI (или .NET 8 SDK и MSBuild) и PowerShell 7.

1. Создайте файл секретов для локальной сборки: `pwsh .github/scripts/create_secret_stub.ps1`
2. Соберите `CDPI.sln` для платформы `x64`
3. Запустите `CDPIUI.TrayIcon` от имени администратора, затем `CDPIUI` от имени обычного пользователя

Полезные команды:

| Задача | Команда |
|---|---|
| Модульные тесты | `dotnet test CDPIUI.Tests/CDPIUI.Tests.csproj` |
| Сборка портативной версии | `pwsh .github/scripts/build_portable.ps1` |
| Проверка списка файлов установщика | `pwsh .github/scripts/check_setup_files.ps1` |
| Сборка `Setup.msi` | `dotnet build NewSetup/NewSetup.wixproj -c Release -p:Platform=x64` |

Каждый push в ветки `main`, `dev` и `fix/**` и каждый pull request проверяется в CI (`.github/workflows/ci.yml`): сборка библиотек, тесты и проверка пакетов NuGet на известные уязвимости, сборка приложения и `Setup.msi` (это задание не блокирует проверку), сборка `Update` и `EditHostFile`. Подробности — в [CONTRIBUTING.ru.md](.github/CONTRIBUTING.ru.md).
