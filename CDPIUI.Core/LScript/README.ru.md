# Справочник по LScript

LScript — небольшой язык выражений. Его используют метаданные Магазина, переменные пресетов и строки запуска пресетов.
Реализация находится в `CDPIUI.Core/LScript`:

| Файл | Содержимое |
|---|---|
| `LScriptCore.cs` | Функции значений (`ExecuteScript`, `ExecuteScriptUnsafe`, `LocalCondition`) и действия установки (`RunScript`). |
| `DefaultMessageHandler.cs` | Вспомогательные методы для путей и файлов для `$STATICIMAGE`, `$DYNAMICIMAGE` и `$LOADDYNAMIC`. |
| `LScriptMsiHandler.cs` | Действие установки `install_msi`. |

Главное окно (GUI) добавляет одну функцию в `CDPIUI/Helper/LScript/LScriptLangHelper.cs` (см. «Расширение GUI»).

LScript состоит из двух частей:

- Функции значений. Они заменяют текст `$FUNCTION(argument)` значением.
- Действия установки. Они выполняют команды после того, как Магазин скачал элемент.

## Функции значений

| Функция | Результат |
|---|---|
| `$STATICIMAGE(path)` | `ms-appx:///Assets/<path>` — изображение в пакете GUI. |
| `$DYNAMICIMAGE(path)` | `<base>\<path>`. `<base>` — аргумент скрипта, если он задан, иначе `Store\Cache\Repo`. Функция не читает файл. |
| `$LOADDYNAMIC(path)` | Текст файла `Store\Cache\Repo\<path>`. |
| `$GETCURRENTDIR()` | Папка вызывающего элемента, `Store\Items\<callItemId>`. Без `callItemId` — папка `Store\Items`. |
| `$GETSRDIR` | Папка кэша репозитория Магазина, `Store\Cache\Repo`. Эту функцию знает только `ExecuteScriptUnsafe`. |
| `$LOCALCONDITION(condition)` | Одно из двух значений. Выбор зависит от логического значения в `jparams`. См. «Условия». |
| `$EMPTY` | Пустая строка. Библиотека удаляет её до вычисления остальных функций. |

Папки `Store\...` находятся в папке данных. См. `CDPIUI.Core/README.md`, раздел «Папки данных».

### Подстановки в аргументах

Если вызывающий код передаёт `scriptArgs`, каждый текст `{...}` в аргументе заменяется на `scriptArgs`.
GUI использует это, чтобы выбрать файл языка. Примеры:

```text
$LOADDYNAMIC(items/zapret/description_{lang}.md)   scriptArgs = "EN"  ->  text of Store\Cache\Repo\items\zapret\description_EN.md
$DYNAMICIMAGE(icon.png)                            scriptArgs = "C:\Temp\ap123"  ->  C:\Temp\ap123\icon.png
```

Имена файлов в этих примерах — только примеры. `LocalItemsInstallerHelper` использует вторую форму.
Он передаёт временную папку набора как `scriptArgs` и читает значок локального набора.
Когда Магазин регистрирует локальный набор, `StoreHelper.GetIconPath` сохраняет значок как полный путь в папке элемента.
Это происходит, только если файл есть в папке элемента. Иначе сохраняется текст `$DYNAMICIMAGE(...)`.

## Режимы вычисления

В библиотеке есть два метода вычисления. Они дают разные результаты.

| Свойство | `ExecuteScript` | `ExecuteScriptUnsafe` |
|---|---|---|
| Где может стоять функция | Только в начале строки. Всё значение должно начинаться с `$`. | В любом месте строки. Заменяются все вхождения. |
| Количество функций | Одна. Текст после вызова игнорируется, кроме случая `$GETCURRENTDIR()`. | Все совпадения. |
| Имена функций | С учётом регистра. | Без учёта регистра. |
| `$GETSRDIR` | Не поддерживается. | Поддерживается. |
| `$GETCURRENTDIR()` | Папка элемента плюс весь текст после `$GETCURRENTDIR()`. | Только папка элемента. Текст после неё остаётся. |
| Результат `$LOCALCONDITION` | Выбранное значение, без раскрытия. | Выбранное значение, снова раскрытое с теми же аргументами. |
| Ошибка | Возвращается входная строка (без `$EMPTY`). | Текст неудачного совпадения остаётся. |
| Кавычки вокруг путей | Нет. | Необязательно (`quotePaths`). |

Строка, которая не начинается с `$`, проходит через `ExecuteScript` без изменений, но без `$EMPTY`.
Неизвестный `$NAME(...)` тоже остаётся без изменений.

### Где используется каждый режим

| Вызывающий код | Режим | Аргументы |
|---|---|---|
| Значения переменных пресета (`ConfigurationService.GetReadyToUseVariables`) | `ExecuteScript` | `callItemId` = id набора, `jparams` пресета |
| Строка запуска пресета после замены переменных (`GetStartupParametersByConfigItem`) | `ExecuteScriptUnsafe` | `callItemId` = id набора, `quotePaths: true` |
| Поиск файлов для пресетов (`Autocorrector`) | `ExecuteScriptUnsafe` | `callItemId` = id набора |
| Значки и тексты Магазина в GUI | `ExecuteScript` через `LScriptLangHelper` | код языка как `scriptArgs` для текстов |

### Порядок для строки запуска

Библиотека раскрывает переменные пресета до того, как раскрывает LScript в строке запуска:

1. Каждая `%NAME%=value` даёт `NAME` = `ExecuteScript(value)`. Значение, которое начинается с `$GETCURRENTDIR` или `$GETSRDIR` (без учёта регистра, после пробельных символов), остаётся без изменений.
2. Библиотека заменяет `%NAME%` в строке запуска (не более 16 проходов).
3. Библиотека заменяет `commaVars`.
4. `ExecuteScriptUnsafe` раскрывает оставшиеся функции, например `$GETCURRENTDIR()`.

Шаг 1 вычисляет остальные значения, которые начинаются с `$`. Значение, которое не начинается с `$`, остаётся текстом.
Затем шаг 4 раскрывает оставшиеся функции и добавляет кавычки вокруг путей. Поэтому путь к папке с пробелами получает кавычки, даже если значение переменной начинается с `$GETCURRENTDIR()`.

Пример пресета в наборе `MyPack`:

```json
{
  "target": ["CSZTBN012"],
  "jparams": { "useGameFilter": true },
  "variables": [
    "%GAMEFILTER%=$LOCALCONDITION(useGameFilter==true ? 1024-65535 $SEPARATOR 12)",
    "%LIST%=--hostlist=$GETCURRENTDIR()/lists/list-general.txt"
  ],
  "startup_string": "--wf-udp=443,%GAMEFILTER% %LIST%"
}
```

Результат, если в пути к папке данных нет пробелов:
`--wf-udp=443,1024-65535 --hostlist=<DataDirectory>\Store\Items\MyPack/lists/list-general.txt`.

## Кавычки вокруг путей

`ExecuteScriptUnsafe` с `quotePaths: true` добавляет кавычки к результату `$GETCURRENTDIR()` и `$GETSRDIR`. Должны выполняться такие условия:

- Путь к папке содержит пробельный символ, например `C:\Users\Ivan Petrov\...`.
- Количество символов `"` перед функцией чётное. То есть функция ещё не в кавычках.

В кавычки берётся только папка. Остальная часть аргумента остаётся после закрывающей кавычки:

```text
--hostlist=$GETCURRENTDIR()/lists/a.txt     ->  --hostlist="C:\Users\Ivan Petrov\CDPIUI\Store\Items\MyPack"/lists/a.txt
--hostlist="$GETCURRENTDIR()/lists/a.txt"   ->  --hostlist="C:\Users\Ivan Petrov\CDPIUI\Store\Items\MyPack/lists/a.txt"
```

Компоненты принимают кавычку в середине аргумента (см. комментарий к `QuoteIfNeeded`).
`ExecuteScript` никогда не добавляет кавычки.

## Условия

Синтаксис:

```text
$LOCALCONDITION(<name>==<true|false> ? <value if equal> $SEPARATOR <value if not equal>)
$LOCALCONDITION(<name>==<true|false> ? <value if equal> : <value if not equal>)
```

Правила (`LScriptCore.LocalCondition`):

- `<name>` — ключ в `jparams`. Условие истинно, если `jparams[name]` равно литералу.
- Литерал должен разбираться как .NET `bool` (`true`, `false`, без учёта регистра).
- Первый `?` завершает условие. Условие не может содержать `?`.
- Если текст содержит `$SEPARATOR`, первый `$SEPARATOR` разделяет два значения.
- Без `$SEPARATOR` значения разделяет первое `:` после `?`. Двоеточие диска (буква, затем `:`, затем `\` или `/`) не считается разделителем.
- Библиотека удаляет пробельные символы в начале и в конце каждого значения. Из выбранного значения она удаляет `$EMPTY`.

Результаты при ошибках:

| Ошибка | Результат |
|---|---|
| Нет `?`, нет разделителя или разделитель стоит до `?` | Пустая строка и предупреждение в логе. |
| Нет `==` или больше одного `==` | Пустая строка и предупреждение. |
| `<name>` нет в `jparams` | Пустая строка и предупреждение. |
| Литерал не равен `true` или `false` | Исключение. Вызывающий код возвращает исходный текст. |
| `jparams` равно `null` | Пустая строка и предупреждение. |

Используйте `$SEPARATOR`, когда значение содержит `:`. ConfigMaker и дополнение ConfigImport всегда пишут `$SEPARATOR`.

Примеры из кода и тестов:

```text
$LOCALCONDITION(useGameFilter==true ? 1024-65535 $SEPARATOR 12)
useA==true?C:\lists\a.txt:D:\lists\b.txt      (test of LocalCondition: drive colons are skipped)
$LOCALCONDITION(useFake==false ? $EMPTY $SEPARATOR --dpi-desync=fake)
```

Тест — `CDPIUI.Tests/Core/LScriptCoreTests.cs`. Третья строка — только пример.

### Вспомогательные методы для условий

- `CreateCondition(name, on, off)` возвращает `"<name>==true ? <on> : <off>"`. Он не добавляет `$LOCALCONDITION(...)`.
- `GetNameOnOffValuesFromConditionString(expression)` читает `%VAR%=$LOCALCONDITION(param==true ? on $SEPARATOR off)`.
  Он возвращает кортеж (`param`, `VAR`, `on`, `off`). Редакторы используют его, чтобы показывать переключатели.
  Без `$SEPARATOR` он использует первое `:` после `?`. Двоеточия дисков он пропускает так же, как `LocalCondition`.

## Действия установки

Магазин выполняет действия установки через `LScriptCore.RunScript`. Они берутся из двух полей элемента:

- `before_install_actions`: выполняются после загрузки и до регистрации в базе данных.
- `after_install_actions`: выполняются после регистрации в базе данных.

Магазин передаёт папку элемента как `CurrentDirectory` обоим спискам.

Действия установки есть только у элементов Магазина и подписанных локальных наборов (`.cdpisignedpack`).
Библиотека игнорирует действия набора без подписи.

### Синтаксис

```text
$<NAME>(<command>, <argument 1>, <argument 2>);$<NAME>(<command>, ...)
```

- `;` разделяет действия. Пустое действие (например, после последнего `;`) пропускается.
- Текст внутри внешних скобок действия содержит команду и аргументы.
- `, ` (запятая и один пробел) разделяет команду и аргументы. Запятая без пробела их не разделяет.
- Имя между `$` и `(` не проверяется. Важно только имя команды.
- Неизвестная команда даёт предупреждение в логе. Затем выполняется следующее действие.
- Отмена останавливает последовательность перед следующим действием.

### Команды

| Команда | Аргументы | Действие |
|---|---|---|
| `finish_component_setup` | имя компонента | Вызывает `ComponentTasksManager.UpdateTaskList`. Для `byedpi`, `spoofdpi` или `nodpi` отправляет уведомление `ProxySetupRequired`, если `PROXY/proxyType` равно `None`. |
| `install_msi` | путь, `true`/`false` | Устанавливает MSI через трей. Второй аргумент указывает, удаляет ли библиотека MSI после установки. |
| `download_easy_designer_annotation_file` | URL HTTPS | Добавляет `DOWNLOAD=<url>$SEPARATORedannotationfile;` к результату `RunScript`. |
| `apply_config` | любые | Ничего не делает. Её пишут старые сборщики наборов. Списки пресетов загружаются заново после каждой установки. |

Имена в первом столбце учитывают регистр и пишутся в нижнем регистре.
Имена компонентов для `finish_component_setup` тоже учитывают регистр.

#### `install_msi`

- Путь задаётся относительно папки элемента (`CurrentDirectory`).
- Полный путь должен оставаться внутри папки элемента. Иначе действие выбрасывает `MsiInstallException`.
- Путь, который заканчивается на `$ALL`, устанавливает каждый файл `*.msi` в этой папке. Подпапки не учитываются.
- Второй аргумент должен разбираться как `bool`. Иначе действие выбрасывает `MsiInstallException`.
- Неудачная установка выбрасывает исключение. Тогда установка элемента завершается ошибкой.
- Установка может длиться не более 30 минут (`MsiInstallerService`).
- Если MSI запрашивает перезагрузку системы, `CoreEvents.RestartRequired` получает имя папки элемента.

```text
$RUN(install_msi, drivers/WinDivert.msi, true)
$RUN(install_msi, redist/$ALL, false);$RUN(finish_component_setup, byedpi)
```

`RUN` и имена файлов — только примеры. Между `$` и `(` допускается любое имя.

#### `download_easy_designer_annotation_file`

Команда не скачивает файл. Она возвращает запись `DOWNLOAD=`.
`OnlineItemsInstallationService.LaunchBeforeInstallActions` читает результат обоих списков действий:

- URL должен быть абсолютным URL HTTPS. Иначе загрузка завершается ошибкой.
- Файл сохраняется в папку элемента с именем `edannotationfile` и расширением файла из URL.
- URL, который заканчивается на `.zip`, распаковывается в папку элемента.

Если загрузка из `before_install_actions` завершилась ошибкой, установка элемента завершается ошибкой.
Если загрузка из `after_install_actions` завершилась ошибкой, библиотека пишет предупреждение в лог. Элемент остаётся установленным.

## Расширение GUI

`LScriptLangHelper.ExecuteScript` (в проекте `CDPIUI`) добавляет одну функцию:

| Функция | Результат |
|---|---|
| `$Q_LINK(key)` | Локализованная строка GUI `<scriptArgs><key>` из ресурсов WinUI3Localizer. |

Все остальные строки передаются в `LScriptCore.ExecuteScriptWork`.

GUI также использует `GetScriptArgs` и `GetArgumentsFromScript`, чтобы прочитать аргумент текста `$NAME(...)`, например URL.

## Ключи в именах пресетов

Имена пресетов — не LScript. `ConfigurationService` заменяет каждый `$WORD(key)` в поле `name` пресета.
Замена — значение `key` в файле локализации набора (`localized_strings_directory` в `init.json`).
При сохранении пресета файл сохраняет исходное имя с ключами.

## Ограничения

- Скобки в аргументе должны быть сбалансированы. Аргумент может содержать вызов, например `$LOCALCONDITION(useA==true ? $GETCURRENTDIR()/a.txt $SEPARATOR b.txt)`.
- Только `ExecuteScriptUnsafe` раскрывает больше одной функции в строке. Он также раскрывает функции в выбранном значении `$LOCALCONDITION`.
  `ExecuteScript` возвращает выбранное значение без раскрытия. В строке запуска его затем раскрывает шаг 4.
- Условие может проверять только одно логическое значение через `==`. В нём нет `!=`, `&&` и `||`.
- `$LOADDYNAMIC` читает только из кэша репозитория Магазина. Он не использует `scriptArgs` как базовую папку.
- Аргумент действия не может содержать `, ` или `;`, потому что эти символы — разделители.
